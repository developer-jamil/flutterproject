Flutter শেখার নোট · Git ও GitHub

Git হাতবই

প্রতিদিনের কাজে যে কমান্ডগুলো লাগে — কপি করার জন্য এক জায়গায়। নিয়ম একটাই: main সবসময় ছাড়ার যোগ্য, প্রতিটা কাজ একটা ব্রাঞ্চে।

সেটআপ নতুন প্রজেক্ট → GitHub Clone ও remote দৈনিক push / pull Conventional Commits ভুল শোধরানো ও পিছনে ফেরা ব্রাঞ্চে টিম-কাজ গোপন তথ্য ফাঁস

০১একবারের সেটআপ

নতুন পিসিতে একবারই চালাতে হয় — Git এর আচরণ ঠিক করে দেয়।

# নাম-ইমেইল (commit এ কার নাম যাবে)
git config --global user.name "LR Jamil"
git config --global user.email "your@email.com"

# আচরণ ঠিক করা
git config --global init.defaultBranch main
git config --global pull.rebase true      # pull এ history জট পাকাবে না
git config --global rebase.autostash true
git config --global rerere.enabled true   # একই conflict এর সমাধান মনে রাখে

# যাচাই
git config --global --list

০২নতুন প্রজেক্ট GitHub এ পাঠানো

আগে GitHub এ একটা খালি repo বানান — README বা .gitignore এ টিক দেবেন না, দিলে প্রথম push এ conflict হবে।

flutter create my_app
cd my_app
git init                  # flutter create নিজেই করে দেয়, না করলে এটা
git add .
git commit -m "initial commit"
git branch -M main
git remote add origin https://github.com/username/my_app.git
git push -u origin main   # -u দিলে পরে শুধু git push লিখলেই হবে

০৩Clone ও remote বদলানো

অন্যের (বা নিজের পুরনো) repo নামিয়ে নিজের GitHub এ তোলা।

# repo টা নিজের কম্পিউটারে আনা
git clone https://github.com/user/repo.git
cd repo

# এখন কোন GitHub এ connected, দেখা
git remote -v

# পুরনো repo থেকে disconnect
git remote remove origin

# নিজের নতুন (খালি) repo জুড়ে দেওয়া
git remote add origin https://github.com/username/new-repo.git
git remote -v             # নতুন ঠিকানা এল কিনা যাচাই

# নিজের GitHub এ পাঠানো
git branch -M main
git push -u origin main

০৪দৈনিক কাজ — push ও pull

দিনে যতবার কোড বদলাবেন, এই চক্রটাই।

status→add→commit→push 
# কী কী বদলেছে দেখা
git status

# সব পরিবর্তন স্টেজে নেওয়া
git add .

# commit (মেসেজে কী করেছেন লিখুন — নিচের ০৫ নম্বর নিয়মে)
git commit -m "feat(profile): add user avatar"

# GitHub এ তোলা
git push

Pull — GitHub থেকে নতুন কোড নামানো

অন্য পিসি থেকে কাজ করলে, বা টিমের কেউ push করলে — কাজ শুরুর আগে সবসময়:

git pull
অভ্যাস: সকালে বসেই git pull, উঠার আগে git push। তাহলে কখনো "আমার পিসিতে তো ছিল" সমস্যায় পড়বেন না।

০৫Conventional Commits

মেসেজের শুরুর শব্দটাই বলে দেয় commit টা কী ধরনের। ছাঁচ: type(scope): কী করলাম

Prefixকখনউদাহরণ
featনতুন ফিচার বা স্ক্রিন যোগfeat(auth): add fingerprint login
fixbug, error বা crash ঠিকfix(cart): fix total price calculation
docsREADME বা ডকুমেন্ট বদলdocs: add installation step in readme
styleরং, spacing, UI সাজstyle(home): change banner padding
refactorকোড re-write / optimize (আচরণ এক)refactor(user): simplify profile logic
perfspeed বা performance বাড়ানোperf(image): optimize image caching
testটেস্ট লেখাtest(auth): add validation unit tests
buildgradle বা dependency বদলbuild: bump gradle wrapper to 9.31
ciGitHub Actions / CI scriptci: add workflow for testing
choreটুকটাক (gitignore, ফোল্ডার গোছানো)chore: update gitignore for keys
revertআগের commit ফিরিয়ে নেওয়াrevert: revert feat(auth) changes

০৬ভুল শোধরানো ও পুরনো commit এ ফেরা

পরিস্থিতি ধরে ধরে — উপর থেকে নিরাপদ, নিচের দিকে বিপজ্জনক।

এখনো commit করিনি — পরিবর্তন ফেলে দিতে চাই

git restore file.dart            # এক ফাইলের বদল উধাও
git restore .                    # সব ফাইলের বদল উধাও (সাবধানে)
git restore --staged file.dart   # ভুলে add করা ফাইল unstage

শেষ commit এ কিছু ভুলে গেছি

git add .
git commit --amend --no-edit     # শেষ commit এর সাথে জুড়ে যাবে

পুরনো commit দেখা ও ঘুরে আসা

git log --oneline                # সব commit এর তালিকা, ছোট sha সহ
git switch --detach a1b2c3d      # ওই সময়ের কোডে ঘুরে দেখা
git switch main                  # বর্তমানে ফেরত

একটা পুরনো commit বাতিল করা — নিরাপদ পথ

git revert a1b2c3d               # উল্টো একটা নতুন commit বানায়
revert কেন সেরা: ইতিহাস মোছে না, উল্টে দেয়। push করা commit এর জন্য এটাই একমাত্র ঠিক পথ।

শেষ commit-ই মুছে ফেলা (এখনো push করিনি)

git reset --soft HEAD~1          # commit গেল, কোড রয়ে গেল
git reset --hard HEAD~1          # commit ও কোড দুটোই গেল ⚠
⚠ --hard মানে চিরতরে। আর push করা commit এ কখনো reset বা amend নয় — করতেই হলে git push --force-with-lease, কখনো খালি --force নয়।

০৭ব্রাঞ্চে টিম-কাজ — ২/৩ জন মিলে

নিয়ম: কেউ সরাসরি main এ push করবে না। প্রত্যেকের কাজ নিজের ব্রাঞ্চে, main এ ঢোকে PR দিয়ে।

  1. কাজ শুরুর আগে main তাজা করুন:
    git switch main
git pull
  2. নিজের কাজের ব্রাঞ্চ খুলুন — নামে কাজটা বোঝা যাবে:
    git switch -c feat/gift-screen
  3. কাজ করুন, commit করুন (দিনে কয়েকবার), ব্রাঞ্চটা GitHub এ তুলুন:
    git add .
git commit -m "feat(gift): add gift bottom sheet"
git push -u origin feat/gift-screen
  4. GitHub এ গিয়ে Pull Request খুলুন (বা টার্মিনালে gh pr create --fill)। টিমের আরেকজন diff পড়ে দেখবে — ভুলে রাখা print, TODO এখানেই ধরা পড়ে।
  5. ঠিক থাকলে Merge চাপুন, ব্রাঞ্চ মুছে দিন। তারপর সবাই:
    git switch main
git pull

দুজনের কোড লেগে গেলে (conflict)

# নিজের ব্রাঞ্চে থেকে main এর নতুন কোড টেনে আনুন
git switch feat/gift-screen
git pull origin main

# conflict হলে Git ফাইলে <<<< ==== >>>> চিহ্ন বসাবে —
# Android Studio তে খুলে কোন অংশ রাখবেন বেছে নিন, তারপর:
git add .
git commit
git push
ব্রাঞ্চ ছোট রাখুন: আয়ু কয়েক ঘণ্টা থেকে বড়জোর ২ দিন। যত ছোট ব্রাঞ্চ, তত ছোট conflict। আর একা কাজ করলেও PR খোলার অভ্যাস রাখুন — diff পড়া, CI, আর "কেন এই বদল" এর স্থায়ী রেকর্ড, তিনটাই ফ্রিতে পাবেন।

০৮গোপন তথ্য ফাঁস হলে

keystore, API key বা password ভুলে push হয়ে গেলে — ক্রমটা এই সাজেই।

# আগে খুঁজে দেখুন কোনো repo তে আছে কিনা
git log --all --full-history -- "*.jks" "android/key.properties" ".env"
  1. আগে চাবিটাই বদলান / বাতিল করুন। ইতিহাস মোছা যথেষ্ট নয় — clone, fork, CI লগে কপি থেকে যায়। public repo তে push মানেই ধরে নিন ফাঁস।
  2. তারপর ইতিহাস মুছুন: git filter-repo --sensitive-data-removal --invert-paths --path <file> (আগে তাজা clone নিতে হয়)
  3. git push --force --all ও --force --tags, শেষে GitHub Support কে ক্যাশ মুছতে বলুন।
আগে থেকেই ঠেকান: .gitignore এ *.jks, key.properties, .env রাখুন — প্রথম commit এর আগেই।
Flutter শেখার পথে বানানো নোট · কমান্ডগুলো কপি করে টার্মিনালে চালান — মুখস্থ নয়, অভ্যাস।
