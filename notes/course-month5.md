# মাস ৫ — ছাড়া ও গুছিয়ে নেওয়া (সপ্তাহ ১৭–১৮ · ১৪ – ২৭ ডিসেম্বর)

> **এই মাসের চরিত্র:** কোড শেখা শেষ — এখন **পেশা**। অ্যাপ দুই স্টোরে ছাড়া, ছাড়ার পরের বাস্তবতা সামলানো, ক্লায়েন্টের কাজ কীভাবে নেওয়া-দেওয়া হয়, আর চার মাসের সব গুছিয়ে portfolio। মাত্র ২ সপ্তাহ, কিন্তু এটাই আপনাকে "শিখছি" থেকে "কাজ করি" তে নেয়।

## সপ্তাহ ১৭ — প্রকাশ ও ক্লায়েন্ট-কাজের কাঠামো

**সপ্তাহের লক্ষ্য:** testing track থেকে production, ছাড়ার পরের নজরদারি, আর পেশাদারভাবে ক্লায়েন্টের কাজ নেওয়ার নিয়ম।

### দিন ১ — Play Store production

**১. testing থেকে production release** · ⏱ ১২০ মিনিট · রিলিজ

📋 মাস ৪ এর internal track থেকে production এ তোলা: store listing (বিবরণ, স্ক্রিনশট, feature graphic), content rating প্রশ্নমালা, data safety form (মাস ৪ এর privacy এর সাথে মিলিয়ে), staged rollout (⚠️ ১০০% নয় — ২০% দিয়ে শুরু, crash না বাড়লে বাড়ান)।

⚠️ প্রথম রিলিজে review কয়েক দিন লাগে; পরেরগুলো দ্রুত। staged rollout না দিলে একটা বাগ সব ইউজারকে একসাথে মারবে।

✓ যাচাই: staged rollout বুঝেছেন? খারাপ build রুখতে rollout halt কোথায়?

### দিন ২ — App Store review

**১. যে কারণে reject হয়** · ⏱ ১২০ মিনিট · রিলিজ

📋 App Store Play Store এর চেয়ে কড়া — সাধারণ reject: crash/bug, অসম্পূর্ণ তথ্য, অ্যাকাউন্ট-মোছা নেই (মাস ৪), digital goods এ IAP বদলে বাইরের পেমেন্ট (মাস ৪ Play Billing নীতি — Apple এ আরও কড়া), privacy label ভুল, "অ্যাপ যথেষ্ট কাজের নয়"। reject হলে কী করবেন: reviewer এর বার্তা পড়ে ঠিক করা, Resolution Center এ উত্তর।

✓ যাচাই: নিজের অ্যাপকে reject checklist দিয়ে যাচাই করেছেন?

### দিন ৩ — ছাড়ার পরের নজরদারি

**১. Crashlytics ও Analytics পড়া** · ⏱ ১২০ মিনিট · পর্যবেক্ষণ

📋 লেখা নয়, **পড়া শেখা**: Crashlytics এ crash-free rate, কোন crash কত ইউজারকে মারছে, stack trace (মাস ৪ এর obfuscation symbol লাগবে)। Analytics এ কোথায় ইউজার ছেড়ে যায় (funnel), কোন ফিচার ব্যবহার হয়। ⚠️ সব crash সমান নয় — ১ জনের vs ১০০০ জনের, অগ্রাধিকার দিন।

**২. backend নজরদারি** · ⏱ ৬০ মিনিট · পর্যবেক্ষণ

📋 আপনার সার্ভারে কী দেখবেন: error rate, ধীর endpoint, ব্যর্থ payment/webhook (মাস ৩), অস্বাভাবিক প্যাটার্ন (হঠাৎ এক account থেকে হাজার request = fraud/bot)। আপনার Zero2Hero backup + Agora usage sync অভিজ্ঞতা (মেমরিতে) এখানেই কাজে আসে।

### দিন ৪ — ছাড়ার প্রথম সপ্তাহ ও ASO

**১. প্রথম সপ্তাহ সামলানো** · ⏱ ৯০ মিনিট · পর্যবেক্ষণ

📋 hotfix প্রক্রিয়া (মাস ৪ flavor/rollout দিয়ে দ্রুত ঠিক), review এর উত্তর দেওয়া, force-update দরকার হলে (এখানেই সেই যোগ করা টপিক — version check + update dialog)। ⚠️ আতঙ্কে সরাসরি main এ push নয় — মাস ১ এর branch/PR অভ্যাস এখানেও।

**২. ASO ভিত্তি** · ⏱ ৬০ মিনিট · প্রকাশ

📋 title/keyword, প্রথম দুই স্ক্রিনশট (এখানেই ইনস্টল ঠিক হয়), rating চাওয়ার সঠিক মুহূর্ত (in_app_review — ভালো অভিজ্ঞতার পর, ঝামেলার মাঝে নয়)।

### দিন ৫–৬ — ক্লায়েন্ট-কাজের কাঠামো (পেশার আসল অংশ)

**১. Requirement থেকে scope** · ⏱ ১২০ মিনিট · পেশা

📋 ক্লায়েন্ট "একটা live অ্যাপ চাই" বলল — এখান থেকে লিখিত scope এ পৌঁছানো: প্রশ্ন করে অস্পষ্টতা দূর, feature তালিকা, কী **এই দফায় নয়** (scope creep আটকানোর একমাত্র উপায়), acceptance criteria।

⚠️ সবচেয়ে দামি শিক্ষা: মুখের কথা নয়, **লিখিত scope**। "আপনি তো বলেছিলেন..." তর্ক এড়ানোর একমাত্র রক্ষা।

**২. সময়, দাম, ঝুঁকি** · ⏱ ১২০ মিনিট · পেশা

📋 estimation (feature ভেঙে সময়, তারপর buffer — আপনার প্রথম হিসাব প্রায় সবসময় কম), pricing মডেল (fixed vs hourly vs retainer — কখন কোনটা), payment milestone (advance + ধাপে ধাপে, শেষে সব নয়), ঝুঁকি (ক্লায়েন্ট উধাও, scope বাড়া, third-party নির্ভরতা)। SDLC ও Agile: sprint, ক্লায়েন্টকে নিয়মিত demo।

✓ জমা: একটা কাল্পনিক (বা আসল) প্রজেক্টের scope নথি + estimate + milestone — যেন কাল ক্লায়েন্টকে পাঠানো যায়।

## সপ্তাহ ১৮ — চূড়ান্ত পরীক্ষা ও গুছিয়ে নেওয়া

**সপ্তাহের লক্ষ্য:** পুরো ১৭ সপ্তাহ যাচাই, দুর্বল জায়গা মেরামত, portfolio, আর সামনের পরিকল্পনা।

### দিন ১–২ — চূড়ান্ত পরীক্ষা

**১. পুরো কোর্সের হাতে-কলমে পরীক্ষা** · ⏱ দুই দিন · মূল্যায়ন

📋 কাগুজে নয় — একটা **নতুন ছোট ফিচার শূন্য থেকে ship**, সব স্তর ছুঁয়ে:
- contract (OpenAPI) → model (freezed) → repository (Result) → provider → UI
- auth-protected, authorization যাচাই (BOLA-নিরাপদ)
- অন্তত ৫টা test, CI সবুজ
- branch → PR → merge (মাস ১ অভ্যাস)
- একটা realtime বা payment উপাদান

⏱ সময় ধরে করুন — এটাই মাপবে চার মাসে গতি কতটা এসেছে।

✓ যাচাই: বাইরের সাহায্য/AI ছাড়া কোন কোন ধাপ পারলেন, কোথায় আটকালেন — সৎ তালিকা।

### দিন ৩ — দুর্বল জায়গা মেরামত

**১. ফাঁক ভরাট** · ⏱ ১২০ মিনিট · মূল্যায়ন

📋 পরীক্ষায় যেখানে আটকেছেন — সেই টপিকে ফিরে যান (state? test? auth? realtime?)। ⚠️ নতুন কিছু শেখার চেয়ে দুর্বল ভিত মজবুত করা এখন বেশি জরুরি।

### দিন ৪ — Portfolio ও GitHub

**১. GitHub গোছানো** · ⏱ ১২০ মিনিট · ক্যারিয়ার

📋 প্রতি মাসের প্রজেক্ট (profile, News, mini-live) — পরিষ্কার README (কী, কেন, স্ক্রিনশট/GIF, architecture, চালানোর নিয়ম, কী শিখলাম), pinned repo, profile README। ⚠️ ক্লায়েন্টের গোপন কোড public এ নয় — sanitized ডেমো বা private+invite।

**২. উপস্থাপনা** · ⏱ ৬০ মিনিট · ক্যারিয়ার

📋 এক পাতা: কী পারেন (Flutter + secure backend + দুই স্টোর প্রকাশ), প্রমাণ (repo/অ্যাপ লিংক)। আপনার আসল শক্তি — চালু production live অ্যাপের অভিজ্ঞতা — সামনে আনুন।

### দিন ৫ — পুনর্ব্যবহারযোগ্য টেমপ্লেট

**১. starter template** · ⏱ ১২০ মিনিট · উৎপাদনশীলতা

📋 চার মাসে বারবার লেখা জিনিস এক জায়গায়: feature-first কাঠামো, Dio+interceptor+refresh, Result, theme/design system, router+auth guard, ci.yml, secure storage, json_helper। এটাই পরের প্রতি প্রজেক্টে দিন-১ বাঁচাবে।

✓ যাচাই: template থেকে নতুন প্রজেক্ট বানিয়ে ৩০ মিনিটে auth+এক স্ক্রিন দাঁড় করাতে পারেন?

### দিন ৬ — ২০২৭ এর পরিকল্পনা

**১. সামনের পথ** · ⏱ ৯০ মিনিট · পরিকল্পনা

📋 কোথায় গভীরে যাবেন (নিজের live অ্যাপের advanced realtime? backend নিজে লেখা? iOS দক্ষতা?), কোন দক্ষতা আয় বাড়াবে, শেখা চালু রাখার রুটিন (মাসে ১ নতুন টপিক)। নিজের তিন অ্যাপের জন্য একটা technical roadmap।

✓ **কোর্স-শেষের চূড়ান্ত যাচাই:** 
- দুই স্টোরে প্রকাশিত/testing-এ অন্তত একটা অ্যাপ ✓
- একটা পুনর্ব্যবহারযোগ্য template ✓
- নিজের backend নিরাপদ করার লিখিত অভ্যাস + অডিট ✓
- ক্লায়েন্টকে scope+estimate পাঠানোর ক্ষমতা ✓
- AI ছাড়াও critical path নিজে লেখা ও যাচাইয়ের আত্মবিশ্বাস ✓

🎓 এই পাঁচটা পারলে — কোর্স শুধু শেষ নয়, সফল।
